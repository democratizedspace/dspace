### Accepted API v1 security scope

The release owner chose the current documented API v1 protections for v3.1.0, subject to QA and
honest disclosure of the relay trust assumption. The browser trusts the compute public key supplied
through the configured relay over HTTPS; it does not independently authenticate compute identity.
Requests currently use AES-CBC; the response decoder supports AES-GCM and CBC compatibility.
CBC does not provide authenticated integrity, and protocol/request-id/client-key envelope checks
are not a substitute for cryptographic integrity. Verify the implemented transport and envelope
checks against the selected token.place candidate and record the actual request/response cipher
formats. Do not claim independent compute identity authentication exists.
A new independent identity/authentication design is a follow-up, not a v3.1.0 release blocker.
This decision does not waive ciphertext-only/no-secret invariants, compatibility QA, or staging gates.

### 11.2a Chat relay proxy: required configuration gates

The chat relay proxy is **optional and default-disabled**. `relayProxyAvailable` in `/config.json`
is `false` and the browser client uses the direct token.place relay path unless an operator
explicitly configures **all five** of the following:

| Variable                                   | Purpose                                                                                        |
| ------------------------------------------ | ---------------------------------------------------------------------------------------------- |
| `DSPACE_CHAT_PROXY_TOKEN`                  | HMAC signing secret for HttpOnly session cookies                                               |
| `DSPACE_CHAT_PROXY_RATE_LIMIT_REDIS_URL`   | Redis-compatible shared rate-limit backend URL (also used for correlation token storage)       |
| `DSPACE_CHAT_PROXY_RATE_LIMIT_REDIS_TOKEN` | Redis-compatible shared rate-limit backend token                                               |
| `DSPACE_CHAT_PROXY_PUBLIC_ACCESS=true`     | Explicit operator opt-in                                                                       |
| `DSPACE_CHAT_PROXY_AUTHORIZATION_TOKEN`    | Pre-shared value; a trusted entry point must supply it via `x-dspace-chat-proxy-authorization` |

Optional sub-operation budget overrides:

| Variable                                 | Default | Purpose                                                                          |
| ---------------------------------------- | ------- | -------------------------------------------------------------------------------- |
| `DSPACE_CHAT_PROXY_SUBOP_SELECT_LIMIT`   | 60      | Per-session per-minute limit for `select` sub-operations                         |
| `DSPACE_CHAT_PROXY_SUBOP_RETRIEVE_LIMIT` | 200     | Per-session per-minute limit for `retrieve` sub-operations                       |
| `DSPACE_CHAT_PROXY_SUBOP_COMPLETE_LIMIT` | 120     | Per-session per-minute limit for `complete` attempts; derived as described below |

Without a completion override, the limit is `DSPACE_CHAT_PROXY_SESSION_LIMIT` (default 20)
multiplied by `(300 / 60 + 1)`: the 300-second correlation TTL divided by the 60-second rate-limit
window, plus one window. Thus the default is 120/min and changes with the configured session limit.

Source references: [proxy implementation](../../frontend/src/pages/api/chat.ts) and
[offline metrics regression tests](../../tests/metricsFallback.test.ts). Passing those tests does
not replace the staging checks below.
