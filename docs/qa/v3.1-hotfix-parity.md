# v3.1.0 gate: account for the complete v3.0.2 maintenance delta

This is a **release-blocking companion to [v3.1 QA](v3.1.md)**, not a port,
deployment receipt, or authorization to publish. Before releasing or promoting
v3.1.0 to production, account for every portable safeguard below with reviewed implementation
or demonstrated equivalent behavior, passing regression evidence, and fresh
candidate evidence where required. An unexplained exclusion blocks release.
G1–G6 are pre-promotion gates; the separate post-promotion verification below is
required for release completion, not for authorizing promotion. All acceptance
gates start unchecked; source inspection alone closes none of them.
Existing v3.1 token.place behavior, security scope, QA requirements, and historical
evidence remain in force.

      at least 24.22.1**, for both the application image and remote browser smoke
      image. Check the current official Node security advisory when choosing it;
      the October hotfix pin is a historical floor, not proof it remains secure.
      Record advisory URL/date and the selected patch. Do not merely allow an
      arbitrary newer major or retain a vulnerable patch to match old fixtures.
- [ ] Align development pin, package/lockfile engine constraints, all setup-node
      consumers, remote-migration and Completionist entry points, app build/final

      Keep application version 3.1.0; chart version remains an independent coordinate.
      Pin reproducible image inputs for native amd64 and arm64 and retain frozen
      dependencies, TLS validation, and no runtime dependency/browser installation.
- [ ] Add or demonstrate automated negative controls for stale Docker/runtime,
      stale `.nvmrc`, hardcoded CI drift, remote runner drift, lockfile/engine drift,
      and inconsistent application coordinates. Adapt the maintenance check's
      literal 3.0.2 and 24.22.1 assertions to v3.1 and the agreed patch; do not
      delete the assertions to make the check pass. Include both image runtimes.

### G4 — Bounded registry reads and durable recovery receipts

- [ ] Demonstrate bounded post-publication read recovery: only selected transient
      HTTP/transport failures retry; four attempts maximum, fresh 30-second abort
      signal covering headers **and body**, bounded 1/2/4-second backoff, and no
      renewal of a successful token just because the index read fails. Redirects,
      auth denials, certificates, uncoded `fetch failed`, invalid JSON/schema,
      digest mismatch and invalid architecture sets fail closed. Never apply this
      read retry loop to absence checks, builds, pushes, or failed smoke tests.
- [ ] Hash received bytes and independently check digest headers against recorded
      build/publication metadata. Require exactly one Linux amd64 and one Linux
      arm64 manifest; allow non-Linux attestation entries without accepting
      duplicate/missing runtime architectures. Verify manifests/configs/labels,
      not only a mutable tag or `NODE_VERSION` environment label.
- [ ] Persist publication separately from verification: record source/tree,
      workflow control SHA, run/attempt, index/platform digests, completed smokes,
      failure stage and timestamps. `published: true, verified: false` stays a
      failure. Save partial progress; mark verified only after all required probes.
      Verification-only retries never publish/rebuild or overwrite prior receipts.
      Link original run and artifact ID/name and preserve evidence before expiry.
- [ ] Exercise sanitized diagnostics and actual fetch/body deadlines with local
      fault injection as well as mocks. Never print tokens, credential-bearing
      errors, response bodies or signed redirects. Wire standalone tests into CI
      with visible output and bounded execution; mocked pass is not runtime proof.

Evidence: maintenance
[read fault-injection suite](https://github.com/democratizedspace/dspace/blob/3fc694b3bf21d8264ded8033b9a39815a8fc120b/scripts/test-maintenance-image-reads.mjs)

and negative test commands/results; workflow run/attempt and artifact links;

mode; UTC timestamp; limitations and reviewer. Record an exclusion against its
