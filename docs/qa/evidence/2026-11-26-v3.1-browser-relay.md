Chromium: **10 passed, 2 skipped** (the two OpenAI deployment-default cases
are not applicable to the token.place-default run). Vitest: **241 passed**
across five suites. The browser tests used route fixtures and blocked other
cross-origin requests for the modified cases. No live provider was contacted.

- **API v1 browser boundary:** A fresh /chat browser sends a quest question and
  renders the fixture assistant response. The exact sequence on the configured
  token.place origin is select, dispatch, retrieve, and acknowledge. The
  selection query contains only the configured model and context tier; no
  plaintext chat-completion call or OpenAI call is made. All four requests omit
  Authorization and Cookie headers. The dispatch is exactly the encrypted
  payload plus the public-key, request, protocol/version, and cancellation
  fields required by the contract; no application metadata, save data, or
  inventory fields are outside the ciphertext. Retrieval and acknowledgement
  use the original request ID and client public key with their scoped protocol
  proofs. A disposable compute fixture can decrypt the request and finds just
  the expected non-streaming API v1 message and routing envelope; it encrypts
  the reply for the public key supplied by the browser, and the browser
  decrypts it and shows the expected text.
- **Persona and docs context:** Selecting Hydro changes the selected persona,
  summary, welcome message, and portrait. The fixture compute receives Hydro's
  system prompt and the relevant docs grounding inside the encrypted request.
  The local chat UI also identifies the docs route source. Separate mock
  browser cases exercised quest progress, process timer, and inventory
  summaries through the OpenAI opt-in path.
- **Credential isolation:** An explicitly saved synthetic OpenAI key does not
  appear in outbound token.place requests, the decrypted compute envelope, or
  rendered prompt messages after switching to token.place. The scoped retrieval
  and acknowledgement proofs also do not appear in the displayed prompt.
  Those proofs belong on their corresponding protocol requests; they are not
  user account credentials or arbitrary application metadata.

This qualifies only the tested browser and local client behavior. It does not
establish live provider interoperability, relay state/log behavior, all storage
or export paths, independent compute identity or cryptographic integrity,
authenticated proxy behavior, cancellation support, or staging/production
release sign-off. The general local contract sign-off remains partial.
