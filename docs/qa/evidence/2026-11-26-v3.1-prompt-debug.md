# v3.1 local token.place prompt debug evidence

**Date:** 2026-11-26 UTC. **Source:**
`30e88dd2ed6af4719fab5711252c90284c03273f` with the accompanying test change
([provider routing spec](../../../frontend/e2e/chat-provider-routing.spec.ts),
Git blob `af4b612ae533c2d606547e6761e80c38ac001d45`). No application behavior changed.

With the workspace lockfile installed and the Playwright browser available:

```bash
npm run build:meta
npm run build:docs-rag
cd frontend
DSPACE_ENV=dev DSPACE_DEFAULT_CHAT_PROVIDER=token-place \
  PLAYWRIGHT_PORT=4241 npx playwright test e2e/chat-provider-routing.spec.ts \
  --project=chromium --grep 'persona switching and debug'
```

**Result:** one focused browser case passed in a local Astro production
build on Node 24.22.3 and Playwright 1.54.2 Chromium 139.0.7258.5 (build 1181).

- The browser saves a synthetic OpenAI key, switches back to token.place,
  selects Hydro, and sends a game question. OpenAI and other non-fixture
  provider traffic are blocked. A disposable relay and compute fixture
  decrypts the dispatched message in the local test process.
- The expanded debug panel identifies token.place and its rendered message
  roles, order and text match the decrypted API v1 request after the client's
  boundary whitespace trimming. The final user message is the submitted
  question and docs grounding is labeled RAG.
- The rendered panel omits the synthetic saved OpenAI key and the scoped
  cancellation, retrieval and acknowledgement values from the fixture.
  The test also checks that the synthetic key did not travel to the fixture.

This covers the normal direct token.place browser flow and the tested saved
and relay secrets. It does not establish behavior for arbitrary text pasted
into a prompt, other provider modes, oversized prompts, copied diagnostics,
operational logs, general source-link sanitization, or a deployed candidate.
