# v3.1 relay response metadata evidence

Tested 2026-11-28 UTC on source commit `1b61ba27650a34939100516addfc36a60cf8fbc8` in the
Linux dev workspace with Node 24.22.3. All provider traffic was mocked.

- The encrypted request test decrypts the dispatched fixture and shows that DSPACE sends no
  application metadata, even when the caller provides it. There is no safe application metadata
  to echo, so DSPACE ignores this field on successful replies. Routing and correlation fields
  are separate and unchanged.
- The relay client tests cover absent and unsolicited application metadata. Both cases preserve
  assistant text, decrypted usage, DSPACE source links, and the client-computed context diagnostics.
  Against the unpatched client, the unsolicited metadata case failed because the extra field
  survived. The debug panel test confirms the local diagnostics remain visible and copyable.
- The full relay client and debug panel specs passed (121 tests). From the repository root:

  ```sh
  node scripts/run-vitest.mjs run --config vitest.config.mts \
    frontend/__tests__/tokenPlace.test.js \
    frontend/src/pages/chat/svelte/__tests__/ChatDebugBuildInfo.spec.ts
  ```

- A dev Astro build with token.place as the default provider passed. Playwright Chromium ran
  `e2e/chat-provider-routing.spec.ts` in that configuration: seven passed, with two
  OpenAI-default-only cases skipped. The browser used encrypted local relay fixtures, not a
  live provider.

This evidence covers the local response-handling checkbox only. It does not verify relay-owned
state, staging or production, or the separate deployed metadata checklist item.
