# DSPACE v3.1 local storage and backup evidence

## Scope and source

On November 25, 2026 UTC, two focused Vitest suites passed against DSPACE source
`54401e729dedc0fb97e8991c9a57de6d0cea3108` with the regression tests in this milestone.
No production code changed. The Linux workspace used Node 24.22.3, the unchanged frozen pnpm lockfile,
Vitest 3.2.4, jsdom, and fake IndexedDB. The tests ran in a separate network namespace with egress
disabled. All test records were synthetic; no live credentials, relays, user data, or backup
services were used.

## Evidence

- The [game-state test](../../../frontend/__tests__/gameState/common.test.js) saves an explicit
  OpenAI provider preference and exports using the same serializer as `/gamesaves`. The decoded
  envelope contains the provider preference and its explicit-choice marker. An inert synthetic
  token.place-shaped record passed through the export state override is excluded from the envelope.
  After resetting state, the same save importer restores the preference and sample inventory,
  without reintroducing the token.place-shaped record.
- The [custom-content test](../../../frontend/__tests__/customBackup.test.js) seeds an OpenAI
  provider preference in game-state snapshots. The custom-content-only exporter emits neither
  settings nor a game-state payload, and restoring custom content does not overwrite those game
  snapshots. The exporter uses the same credential sanitizer on its records and final envelope.

Run from the repository root after the unchanged frozen dependency install:

```sh
unshare -Urn node scripts/run-vitest.mjs run --config vitest.config.mts \
  --testTimeout 20000 --maxWorkers=1 \
  frontend/__tests__/gameState/common.test.js frontend/__tests__/customBackup.test.js
```

Both files passed, **29 tests total**. This verifies the local serialization and import/restore
contracts only. It is not evidence of live GitHub backup, primary IndexedDB in a browser, staging,
or production behavior.

## Browser fallback

On November 25, 2026 UTC, the new [browser test](../../../frontend/e2e/indexeddb-availability.spec.ts)
passed against an unchanged local DSPACE dev build from the same application source, using the
repository's Playwright 1.54.2 and its pinned Linux Chromium build 1181. The browser was given a
fresh context with a page initialization script that makes IndexedDB opens throw `SecurityError`.
Service workers were disabled and the new test aborted all requests outside the loopback app origin.
The test opened `/settings`, chose OpenAI without entering a key, verified `settings.chatProvider`
in the full localStorage save, reloaded, and verified that the UI restored the chosen provider.

Reproduce from `frontend` after installing the frozen workspace and preparing the pinned browser
and normal development preview build:

```sh
DSPACE_ENV=dev PLAYWRIGHT_PORT=4274 BASE_URL=http://127.0.0.1:4274 \
  ./node_modules/.bin/playwright test indexeddb-availability.spec.ts \
  --project=chromium --workers=1 -g 'keeps the selected chat provider'
```

**One test passed**. The local preview adapter logged a sandbox interface-enumeration error but
served the app and the test completed. This verifies the localStorage fallback, not the primary
IndexedDB path or storage behavior in a deployed release.
