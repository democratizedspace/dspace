## Safe metadata

The direct relay client test supplies synthetic credential, save, and inventory markers in caller
metadata. The intercepted dispatch request excludes all of those markers as well as the test
OpenAI key, conversation identifier, and plaintext metadata field. Another test decrypts the
fixture envelope and confirms the caller-supplied metadata is not added to the inner request or
its options either. The [prior Chromium evidence](2026-11-28-v3.1-offline-qa-batch.md#relay-and-request-privacy)
checks the exact outgoing transport field set. Together these support the three source-side
metadata exclusions, not relay-owned logs/state or response metadata filtering.

## Proxy endpoint behavior

The runtime config regression compares an all-five configured control with five cases in which
exactly one operator gate is absent. The control reports proxy availability without serializing
private config, and every omission reports false. This checks only the config endpoint, not
hydration, network entry-point behavior, or public asset contents.

The local proxy route returns 403 before upstream calls when the session cookie is absent or
invalid, with OpenAI and token.place calls observed separately. With an authorized synthetic
session, select and retrieve increment exactly one separate sub-operation key each and neither
touches main session or global counters. The test freezes the clock so its quota assertions cannot
cross a wall-clock window boundary. These observations are route-level evidence and do not
qualify live Redis, staging headers, Prometheus scraping, or promotion.
