## Relay proof lifetime

Chromium completed a synthetic encrypted turn and acknowledgement. The test
checks the actual cancellation proof and both fixture-issued proof values
against the visible chat debug panel, browser console and page errors, and
snapshots of localStorage, sessionStorage, and IndexedDB record keys and
values before and after reload. It verifies that the snapshots contain the real game-state database
and provider preference plus the synthetic OpenAI key as positive controls.
The [save and backup tests](2026-11-25-v3.1-storage.md#evidence)
separately cover exclusion of token.place-shaped credentials when serializing
and restoring exports. Scoped proofs observed on the wire are not account
credentials. No server-side or live relay logs were inspected.

## OpenAI key and response metadata boundaries

- The provider routing tests cover selecting OpenAI again after reload and
  completing a stubbed turn with a previously saved key. The local relay turn
  also confirms that the synthetic key never appears in the captured request or
  even in the decrypted prompt. This establishes the supported current save
  path, not migration from earlier credential layouts.
- The relay fixture omitted response metadata entirely and the browser still
  displayed a successful response. The client forwards application response
  metadata when present without verifying that it matches a safe request echo,
  so the full metadata checkbox stays open. This is separate from validated
  routing metadata and from client-computed diagnostics.

No runtime behavior, release coordinates, publishing, or deployment changed.
