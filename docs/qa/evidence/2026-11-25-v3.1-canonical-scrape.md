## Local render procedure and result

From the DSPACE checkout with the pinned Sugarkube checkout at `$SUGARKUBE`:

```sh
bash scripts/check-dspace-chart-version.sh
helm template dspace charts/dspace --namespace dspace \
  -f "$SUGARKUBE/docs/examples/dspace.values.staging.yaml"
helm template dspace charts/dspace --namespace dspace \
  -f "$SUGARKUBE/docs/examples/dspace.values.prod.yaml"
```

Parsed both renders as YAML. Each contained exactly one ServiceMonitor with the expected
`release` selector label, named namespace `dspace`, and selectors that match the rendered
DSPACE Service. Both select the named `http` Service port at `/metrics`, reference the
overlay's bearer Secret key `token` without rendering a credential, and relabel the environment
as `staging` or `prod`, respectively.

This is source and local render evidence, not evidence for a published chart, loaded
Prometheus configuration, network reachability, credential validity, scrape results, or
staging or production acceptance. Recheck with the exact candidate chart and environment
values before promotion. No live endpoint, cluster, registry, tag, or deployment was changed.
