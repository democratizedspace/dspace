# K078 import and credential safety

Implements approved phases A–C against proposal/main commit `20ba6f4513a3c84ea928bfdc70269a6bd7861672`. Fresh main matched that base. Phase D remains deferred.

## Import contract

Raw game objects, UTF-8 JSON, base64 JSON, file input and embedded custom content share pure preparation. Schema 1 envelopes and sparse legacy records are explicit adapters. Historical browser game exports made with `btoa(JSON.stringify(...))` use an explicit Latin-1 fallback only when UTF-8 decoding fails and the parsed object has a recognized legacy game shape; all decoded JSON/graph/schema budgets still apply. New exports remain UTF-8. Version 1 item `price`, `unit` and `type` null defaults normalize to absent fields; null item images use the bundled fallback and export as absent; other malformed null fields still reject. Numeric process durations normalize to explicit seconds strings consumed by the runtime; supported textual durations remain compatible. Wrong types, duplicate JSON keys, prototype keys, cycles, accessors, unsupported versions, colliding normalized IDs and invalid references reject before writes. Errors contain bounded codes and structural paths, never submitted values.

Provisional caps: 24 MiB transport, 16 MiB JSON, depth 64, 100,000 nodes, 256 ordinary object keys, 10,000 map entries/array elements, 2,000 entities and image records, 64 KiB ordinary strings, 256-byte IDs, 2,048-byte URLs, 2 MiB per raster/8 MiB aggregate encoded raster bytes, and 4 million pixels per raster/16 million total. Each image occurrence counts. New custom-content exports keep item/quest raster data only in image records, avoiding duplicate entity payloads while preserving the same import budgets. Unit tests inject small caps to exercise boundaries without stress allocations. These caps are policy defaults, not measured universal device safety thresholds.

Static PNG, JPEG, GIF and WebP receive structural metadata validation before browser rendering; animation and SVG reject. This does not replace a complete codec decoder. Routes are canonical internal routes; remote images require HTTPS, or same-origin URLs. Credentials in URLs, controls, backslashes and protocol-relative URLs reject. Literal angle-bracket defenses remain. Existing tiny PNG test fixtures had invalid IDAT CRCs and were replaced with generated synthetic images.

Imported provider configuration and credential authority cannot replace destination credentials. Export filtering covers the entire game/custom-content envelope using the existing known-sensitive-field policy. That policy matches substrings (including `auth`), so extension fields such as `author` are also omitted. K078 preserves that filtering contract; narrowing it requires a separate reviewed policy change.

## Commit and recovery contract

Game state, backup and metadata commit in one IndexedDB transaction. Custom items, processes, quests and revision metadata commit in a separate transaction. Completion events provide receipts; request success alone does not. Preparation finishes and required schemas are preflighted before mutation. Import never runs custom-content migrations. Destination numeric/whitespace ID aliases participate in normalized conflict checks. If an imported ID would rename an existing legacy key, standalone and combined restores reject with `legacy-id-migration-required` before committing either database; migrating retained inventory/quest references is not performed implicitly. Canonical additive conflicts reject, and canonical overwrite retains its normal behavior.

Managed operations use immutable queued snapshots and a Web Lock shared by compatible tabs. Transactions compare game checksum/credential epochs or custom-content revision plus preflight rows. Missing lock support fails closed for managed imports and credential operations. Startup and ordinary gameplay retain an explicit credential-free localStorage fallback without IndexedDB writes. Startup reads existing IndexedDB progress without migrations and compares existing save timestamps so IDB-only saves and newer fallback progress survive reload. A tab that enters fallback stays there for ordinary saves and game-only imports until reload; credential Save and custom-content imports require reload, while targeted Clear remains available. Startup after storage or lock support returns reconciles newer fallback progress through a checked game transaction while retaining durable credentials, epochs and the existing backup. A second-database failure reports the game commit as partial; localStorage mirror failure reports committed databases honestly. There is no cross-database crash atomicity.

Recovery is explicit, bounded, sanitized and in memory only. Partial game recovery refuses intervening changes. When both databases committed, recovery repairs mirrors rather than undoing custom content. Reload or Clear discards recovery. No persistent undo store or generation database is added. Ordinary game-only localStorage fallback is explicitly best effort, propagates errors and excludes credentials.

## Clear contract

The managed inventory is runtime state and registered credential drafts; localStorage `gameState`, `gameStateBackup`, `gameStateLite`, `gameStateChecksum`; and IndexedDB `dspaceGameState` stores `state/root`, `backup/root`, `meta/root`. Owned legacy `gameState` and `payload` wrappers are traversed and checksums regenerated. Unrelated provider fields and unrelated origin data remain intact.

Clear first durably increments the selected provider epoch and records a pending/cleared intent in owned metadata. Scrubbing and readback must finish before reporting complete. Interrupted Clear remains incomplete and gates new requests; retry is explicit. Ordinary saves, rollback, reset and legacy seeding respect authority. Deliberate later credential saving advances authority. Owned metadata retains two scalar Save-run base epochs; Clear resets the selected base. An ordinary queued save can reconcile newer credential-only Saves inside its transaction when durable gameplay still matches its captured base, even before a notice arrives. An intervening Clear, unknown legacy epoch history, pending Clear or changed remote gameplay blocks reconciliation. Cached prompt/retry and multi-request GitHub paths recheck launch authority. Authority checking and actual fetch issuance share one lock reservation; network completion is awaited after releasing the lock. Already issued requests cannot be recalled. Cloud Sync Save/validation errors never automatically clear durable credentials; only an explicit Clear does so, preventing an older validation failure from deleting a newer tab's token. Credential edits invalidate displayed backup lists and pending list refreshes without clearing storage.

Close or reload older incompatible DSPACE tabs before relying on Clear: their writers do not participate in these locks/epochs. Clear removes managed local copies; it does not revoke provider credentials or search unrelated origin stores.

Reserved game `payload`/`gameState` wrappers are validated recursively before writes. Malformed wrappers or owned credential/metadata sections reject without mutation; valid legacy wrappers retain unrelated fields while imported credentials and credential authority are excluded at every owned wrapper level.

## Regression and compatibility evidence

`frontend/tests/k078ImportSafety.test.ts` names A01–A06, B01–B06 and C01–C06, with additional table-driven limit/media/fault cases. `k078Coordinator.test.ts` exercises the real coordinator, partial recovery, mirror repair, immutable saves, export filtering, reload/rollback and cached OpenAI prompts. All data and credentials are synthetic; network calls are denied or mocked.

`node scripts/k078-browser-validation.mjs` exercises genuine IndexedDB transactions in Chromium, Firefox, WebKit and Chromium with a 128 MiB V8 heap cap and 4x CPU throttling. It includes a second compatible tab, stale-write rejection and deliberate later credential saving. It writes exact-head/dirty-state evidence under ignored `artifacts/`. The generated compatibility cases contain 1, 100, 1,000 and 2,000 entities (largest about 252 KB), not maximum-size production saves.

Precommit measurements on ESPC: 2,000-entity preparation/commit took about 32/89 ms Chromium, 12/68 ms Firefox, 14/30,342 ms WebKit, and 135/322 ms constrained Chromium. WebKit Windows transaction latency is a material limitation. Browser main-process peak working set and available sampled JS heap are recorded separately; neither measures whole-device or all-renderer peak memory. Unsupported heap observations remain null. The harness must pass again at the final commit; these preliminary numbers are not final-head certification.

Repository-wide validation also encounters baseline failures on ESPC (Windows command/path assumptions and unavailable Helm/build output). An untouched worktree at the proposal base reproduced 45 failures in eight selected baseline suites. Root build additionally invokes `spawn('npm')`, which fails on Windows; direct frontend build reached client compilation then exited with a native access violation. These limitations do not justify skipping final-head GitHub CI. The PR remains draft until applicable reviews and exact-head CI pass.

Exported raster media passes the same static-format, dimension, byte and pixel checks as import; incompatible media stops export and cloud upload before a remote backup is created. The bundled favicon remains a local fallback reference. Once a remote upload succeeds, a local bookkeeping or mirror failure preserves its receipt and displays a separate warning instead of inviting a duplicate upload.

Sparse imports may reference canonical custom IDs already in the destination. Pure preparation validates shapes/media and local dialogue links; destination-dependent item/process/quest/container links are resolved against the preflight snapshot before either database commits. Existing noncanonical legacy IDs still require explicit migration. Revision and complete-row checks reject destination changes during commit.

Completed custom exports pass restore preparation; combined game envelopes use the same dependency-free budget validator before export/upload success, including aggregate entity, graph, ordinary string and JSON budgets. Pretty-printed custom downloads also validate their serialized whitespace overhead. Imported checksums and timestamps are discarded throughout owned wrappers; commits assign local ordering metadata. GitHub quest gates must be boolean at quest and dialogue-option levels.

Legacy numeric item prices normalize to strings consumed by inventory search. Dialogue options require runnable action types and required targets; legacy navigation-only options explicitly become goto actions, with the historical finish sentinel becoming a finish action when no such node exists.

Container replacements also validate affected references in retained destination processes, quests and item links against the post-import catalog before either database commits. Unrelated legacy rows remain unchanged. Numeric duration adapters expand scientific notation and reject values whose runtime milliseconds would overflow.

The legacy custom-backup regression suite is included in repository Vitest. Sparse imported records derive canonical entity type and custom-content metadata from their section, so native get/edit consumers recognize restored records.

If localStorage reads fail during Clear, accessible durable current/backup/metadata copies are still scrubbed and the committed receipt reports that work. Unreadable mirrors are preserved to avoid losing unknown gameplay; Clear remains incomplete with its durable request gate pending until an explicit retry can read, scrub and verify every owned copy.
